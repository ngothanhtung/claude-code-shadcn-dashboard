Organized as a flat set of leaf packages with clear dependency direction:
- `lib/auth/` — NextAuth integration helpers (`admin-api.ts` wraps `auth()` + `hasAdminAccess`) plus role checks in `permissions.ts` (single source of truth: `ADMIN_ROLE_ID`, `ADMIN_EMAIL`) and Firestore-backed authorization resolution in `user-access.ts` via the admin SDK.
- `lib/firebase/` — thin wrappers around Firebase SDKs: `client.ts` bootstraps the singleton `app`/`auth`/`db`/`storage` after validating `NEXT_PUBLIC_FIREBASE_*` env vars; `auth.ts` exposes user-facing auth operations (sign-in, sign-up, profile, notifications, account deletion) using the client SDK; `firestore-query.ts` provides generic typed collection fetchers with local-fallback behavior; `admin.ts` is imported by `user-access.ts` for server-side reads.
- `config/` — static theme metadata (`theme-customizer-constants.ts`, `theme-data.ts`) consumed by the theme manager.
- `hooks/` — pure React hooks built on top of contexts/config: `use-theme-manager.ts` orchestrates CSS variable injection, brand-color extraction, and preset/imported theme application; `use-theme.ts` / `use-sidebar-config.ts` / `use-mobile.ts` / `use-fullscreen.ts` / `use-circular-transition.ts` provide UI state.
- `contexts/` — `theme-context.ts` defines the `ThemeProviderContext` contract; `sidebar-context.tsx` holds sidebar layout state.
- `utils/` — theme preset factories (`shadcn-ui-theme-presets.ts`, `tweakcn-theme-presets.ts`).
- `types/` — shared interfaces (`ThemePreset`, `ColorTheme`, `ImportedTheme`, `BrandColor`, etc.) plus NextAuth declaration augmentation (`next-auth.d.ts`).

Dependency direction is strictly inward: hooks → contexts/config/types; lib/* → firebase client; auth layer → permissions + firebase admin; nothing in this module imports from feature pages.
