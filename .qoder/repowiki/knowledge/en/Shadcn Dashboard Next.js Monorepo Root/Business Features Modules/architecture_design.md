Each child under `src/modules/<feature>/` is a self-contained feature with the same internal layout: a `components/` folder for shadcn/TanStack-based UI, a `services/` folder split into `types/`, mock data (`*-mock-data.ts`), and live data adapters (`*-services.ts`) that query Firebase Firestore. There is no shared orchestration layer between features — they are wired in by the app shell via lazy-loaded routes, and cross-feature communication happens only through the global Zustand store or direct imports from `src/lib/firebase`. The consistent `services/types/<feature>-types.ts` + `services/*-mock-data.ts` + `services/*-services.ts` triad lets every feature swap its backend without touching components.
